# 算子手册导航

本目录是**内置算子的手册与测试数据**，沿用 datamore_lite `graph/operator_md/` 的组织方式：每个算子由三个文件组成，**目录结构与代码目录一一对应**。

```
operator_md/                              lowcode/operators/
├── 算子导航.md                本页        ├── base.py / registry.py
├── <分类>/                                 ├── filter/        校验与断言
│   ├── <算子名>.md         手册            ├── transformer/   结构转换
│   ├── <算子名>.yaml       节点模板        └── external/      外部交互
│   └── <算子名>_input.yaml 用例集              ├── usql/  SQL 数据源（sqlite / mysql）
│                                               ├── uhttp/ HTTP 上游
└── 对应的测试入口在                          └── uredis/ Redis
    tests/operators/<分类>/test_<算子名>.py
```

分类与 datamore_lite 的对应关系：

| 分类 | 职责 | datamore_lite 对应 |
|---|---|---|
| `filter` | 校验与断言，条件不满足即**中断流程** | `filter/paramChecker`（参数校验失败中断 DAG） |
| `transformer` | 只加工数据、决定输出形态 | `transformer/respBuilder`、`respMergeBuilder` |
| `external` | 与外部系统交互，按数据源分 `usql` / `uhttp` / `uredis` | `external/uhttp`、`external/uredis` |
| `aggregate` | 聚合统计 | datamore 预留的 `aggregate/` 目录（未实现），本框架实现 |
| `selector` | 字段投影 | datamore 预留的 `selector/` 目录（未实现），本框架实现 |
| `custom` | 缺省分类（内置算子不使用） | — |

编写方法见 [TESTING.md](../docs/TESTING.md)。

## 算子列表

### external：与外部系统交互

| 算子 | 功能 | 数据源 | 要点 |
|---|---|---|---|
| [sqlQuery](external/usql/sqlQuery.md) | 执行查询 SQL，返回行列表或单行 | sql | 只能用 `:name` 绑定参数；启动期双向核对绑定参数 |
| [sqlExec](external/usql/sqlExec.md) | 在事务中执行写 SQL | sql | 返回 `{rowcount, lastrowid}`；可配合 `readonly` 防止误写 |
| [httpRequest](external/uhttp/httpRequest.md) | 调用上游 HTTP 接口 | http | 非 2xx 返回 502，超时返回 504；超时不会超过接口剩余时间 |
| [redisGet](external/uredis/redisGet.md) | 读 Redis（get / hgetall）并解析 | kv | raw / json / csv 三种格式；键不存在时返回 `default` |
| [redisMGet](external/uredis/redisMGet.md) | 一次批量读取多个键（`MGET`） | kv | 按键顺序拼接；列表型结果自动展开；缺键默认跳过 |

### filter：校验与断言

| 算子 | 功能 | 要点 |
|---|---|---|
| [expectGuard](filter/expectGuard.md) | 断言，不满足时中止并返回 code / msg | 典型用法：查不到数据返回 404 |

### transformer：结构转换

| 算子 | 功能 | 要点 |
|---|---|---|
| [respBuilder](transformer/respBuilder.md) | 按模板组装输出结构 | 通常是最后一个节点；同时覆盖透传和多源合并 |
| [numberCast](transformer/numberCast.md) | 把指定字段的字符串转成数值 | 供 groupBy / listAgg 聚合；不改动上游输出 |
| [rowFilter](transformer/rowFilter.md) | 按字段与阈值过滤行 | 只丢数据不中断接口；阈值支持模板 |
| [dateRange](transformer/dateRange.md) | 把起止日期展开成日期列表 | 含首尾；`limit` 限制最大天数，超限返回 400 |
| [templateMap](transformer/templateMap.md) | 把列表按模板逐项渲染成新列表 | 模板里可用 `item` / `index`；通常用来批量拼 key / URL |

### aggregate：聚合统计

| 算子 | 功能 | 要点 |
|---|---|---|
| [listAgg](aggregate/listAgg.md) | 列表整体统计（count / sum / avg / min / max） | 空数据兜底不报错 |
| [groupBy](aggregate/groupBy.md) | 按字段分组统计 | 按 key 升序，结果顺序稳定 |

### selector：字段投影

| 算子 | 功能 | 要点 |
|---|---|---|
| [fieldPicker](selector/fieldPicker.md) | 按声明挑选字段，缺失补 null | 裁剪响应，输出 schema 稳定 |
| [renameFields](selector/renameFields.md) | 按映射重命名字段 | 只改名；目标字段冲突时报错 |

## 选型指南

| 需求 | 用法 |
|---|---|
| 参数非空、类型、正则、枚举、范围校验 | **不需要算子**，直接在接口的 `inputs` 中声明（对应 datamore 的 `paramChecker` 和 `paramsExtractor`） |
| 查数据库 | `sqlQuery`；只要一行时加 `single: true` |
| 写数据库 | `sqlExec` |
| 读缓存（单个键） | `redisGet`，按值的形态选择 `format` |
| 按日期 / id 批量读缓存 | `dateRange`（或 `templateMap`）生成键列表 → `redisMGet` 一次读完 |
| 把列表拼成一批 key / URL | `templateMap` |
| 统计列改成业务字段名 | `renameFields` |
| 聚合上游接口 | `httpRequest` |
| 多个查询并行 | 把多个数据节点写成 `depends: []`（根节点），再由 `respBuilder` 汇总 |
| 查不到返回 404、业务前置条件 | `expectGuard` |
| 决定响应结构 | 最后一个节点放 `respBuilder` |
| 响应瘦身、只暴露部分字段 | `fieldPicker` |
| 总数 / 金额汇总 | `listAgg` |
| 按状态、日期等维度的分布 | `groupBy` |
| 以上都不满足 | 扩展框架：新增内置算子（见下方检查清单） |

## 与 datamore_lite 算子的对应关系

| datamore_lite | 本框架 | 变化原因 |
|---|---|---|
| `paramsExtractor` + `paramChecker` | 接口的 `inputs` 声明 | 声明即生效，少配一层节点 |
| `stringRedisReader` / `jsonRedisReader` / `csvRedisReader` / `rankRedisReader` | `redisGet` + `format` | 几个读取器只差在值怎么解析 |
| `respBuilder` / `respMergeBuilder` | `respBuilder` | 模板既能透传也能按名字合并，不依赖 depends 的位置顺序 |
| —（预留目录 `aggregate/`，未实现） | `listAgg` / `groupBy` | 新增 |
| —（预留目录 `selector/`，未实现） | `fieldPicker` | 新增 |
| —（旧版配置里的 `querySQLExecutor`） | `sqlQuery` / `sqlExec` | 新增；只允许绑定参数 |
| — | `httpRequest`、`expectGuard` | 新增 |

## 新增一个内置算子：检查清单

1. 在 `lowcode/operators/<分类>/<算子名>.py` 中用 `@register("名字", category="分类")` 注册，并声明 `spec`；
2. 在该分类的 `__init__.py` 加 import（导入即注册，`lowcode/operators/__init__.py` 会自动加载各分类）；
3. 在 `operator_md/<分类>/` 下写三个文件：`<名字>.md`、`<名字>.yaml`、`<名字>_input.yaml`；
4. 新建 `tests/operators/<分类>/test_<名字>.py`（复制任意一个现有文件，改三行）；
5. 在本页的算子列表中加一行。

第 3~5 步由 `tests/operators/test_catalog.py` 强制检查：

- 缺少任何一个文件、手册的 Config 参数表与代码中的 `spec` 不一致（字段名、必填、是否支持模板），或者本页漏列了算子，测试都会失败；
- 这样做是为了让**手册永远与代码同步**。datamore_lite 的 `CONFIG_SPEC.md` 就出现过文档字段与代码对不上的问题。
