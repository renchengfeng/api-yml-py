lowcode 核心一页纸

一张图看懂核心：框 = 代码文件（框内是文件名 / 核心函数 / 职责），箭头 = 跨文件调用（标签是调用点）。 加载期只做一次，调用期每请求一次。

四个分区：加载期（启动一次）→ 调用期（每请求一次）；算子层与基础层是它们共用的支撑。点击函数名可查看完整源码。

数据是怎么流的 · counter/merge

框 = 一个算子：第一行「id · 算子」，第二行是它输出的数据形态，第三行写进黑板哪个 key；箭头上的 {{ }} 就是数据的来源。

读入 → 数值化 → 分组求和 → 过滤 → 输出；每个节点的输出都进 Context._outputs，下游按 id 取。

设计要点

四层模型server → group → api → 算子 DAG；文件名三段即路由，一个接口一个文件。
启动期编译一次YAML → ApiPlan：结构、引用、模板、outputs 对账、依赖探测全在启动期完成，错误前置。
请求期只读计划每个请求只做入参校验、模板渲染、execute 与黑板写入，不再解析 YAML。
三类 config 字段static 原样固化；dynamic 框架编译并渲染；raw 框架不碰、算子自己渲染。
按 id 引用上游节点输出写入黑板，下游用 {{ 节点id }} 读取；只能引用 depends 链上的祖先，启动期校验。
单一职责算子按 filter / transformer / external / aggregate / selector 分类，一个算子只做一件事。
错误分层ConfigError 启动期；ParamError 400；BizError 业务码；ExecError 500；Deadline 504；Upstream 502。
不原地修改args、上游输出、静态 config 在节点间共享；算子必须返回新对象，契约测试强制检查。
测试同路径算子用例与线上都走 compile_node() + run_node()，用例通过 ≈ 线上行为正确。
不提供分支循环guard + 表达式覆盖常见的前置条件；复杂逻辑写成自定义算子，而不是把 YAML 变成编程语言。
一句话记住：加载期只做一次（YAML → ApiPlan），调用期每请求一次（ApiPlan → 响应）。 加新算子 = 在 operators/<分类>/ 写一个类，声明 spec，实现 build() 与 execute()。
