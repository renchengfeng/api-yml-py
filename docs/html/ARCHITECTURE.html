02唯一节点调用关系图 · redisGet

每个 文件:函数 只出现一次；横向 = 调用深度，同列 = 同一层；箭头 = 实际调用，悬停节点或连线可看完整说明。①~⑤ 是 build_runtime 的调用顺序。

左起：阶段 0 注册期（import 时一次）→ 阶段 1 编译期（每接口一次）→ 阶段 2 请求期（每请求一次）。图中不含调用树中的重复节点：同一个函数在多处被调用时只画一个节点，由多条入边表示。

03文件级调用图 · 文件为节点，函数为行为

每个文件一个节点，节点内每一行 = 该文件的一个函数（行为）；节点间的箭头 = 跨文件调用，悬停箭头或节点可看具体调用点。同文件内的调用不画线（见 04 节的行内标注），因此没有 U 形回环、也没有连线堆叠。

横向 6 列：入口层 → 执行层 → 算子层 → 编译层 → 数据源层 → 基础层。跨多列的边走顶部走廊、反向边走底部走廊，每条边单独一条通道，互不重叠。

04数据是怎么流的 · counter/merge

框 = 一个算子：第一行「id · 算子」，第二行是它输出的数据形态，第三行写进黑板哪个 key；箭头上的 {{ }} 就是数据的来源。

读入 → 数值化 → 分组求和 → 过滤 → 输出；每个节点的输出都进 Context._outputs，下游按 id 取。

# conf/demo_counter_merge.yaml（节点 a）
- id: a
  name: "redisGet"          # → get_operator()
  depends: []             # → Graph.levels()
  config:
    dataSource: "mdnf"      # → validate() / build()
    key: "counter|daily|a|{{ inputs.date }}"
                             # → dynamic，编译为 Template
    format: csv            # → validate(choices)
    fields: [date, cnt]    # → parse.check_config()
    default: {date: "", cnt: "0"}
# 编译期产物（概念示意，非仓库文件）
PlanNode(
  id="a",
  op=RedisGet(...),            # spec 校验后的实例
  depends=(),
  static={dataSource:"mdnf", format:"csv",
          fields:["date","cnt"], default:{...}},
  dynamic={key: _Expr("inputs.date")},
  desc="读第一个 key 的日期计数",
)

# 请求期：resolve_args 渲染 → execute
args["key"] = "counter|daily|a|2026-11-04"
ds.get(key) = "2026-11-04|10"
ctx.output("a") = {date: "2026-11-04", cnt: "10"}

07关键约束（决定扩展方式）

  • 三个时机：注册（import 一次）→ 编译（每接口一次：validate / build / compile_template）→ 请求（每次：resolve_args / execute）。把能提前做的事放进 build()。
  • 三类 config 字段：static（原样）、dynamic（框架编译模板、校验引用、每请求渲染）、raw（算子自己渲染，框架不编译不校验，如 templateMap.template）。
  • 引用安全：模板只能引用 inputs / request / 上游节点 id 与 Jinja 全局；inputs.xxx 必须已声明，否则启动期报错。
  • 不得原地修改 args 与上游输出（节点间、请求间共享）；算子测试框架的 _check_untouched 会强制校验。
  • 错误分层：ConfigError 启动期 / ExecError 运行期 500（带 [节点id] 前缀）/ BizError 业务码原样透出 / ParamError 400。
  • 测试同路径：lowcode/testing/suite.py::run_case() 同样调用 compile_node() + Executor.run_node()，算子用例与线上走同一条链路。

查看方式：浏览器直接打开本文件（无外部依赖）；命令行可用 python3 -m lowcode operators 看已注册算子、python3 -m lowcode explain -c conf 看每个接口的编译产物。
